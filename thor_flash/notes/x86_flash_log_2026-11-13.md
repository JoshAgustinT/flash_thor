## Why this procedure (what the BSP code says)
- t264.conf.common sets _UNIFIED_FLASH=1. With `-k`, l4t_initrd_flash skips creating tools/kernel_flash/images/
  and only works on a package from an earlier full run; even then it only prints a flash_bsp_images.py -u command
  (l4t_initrd_flash_internal.sh:1036). The wrapper's real flash step is the same tool (…internal.sh:1335).
- flash_bsp_images.py `-u` takes several partitions (bootburn_t264_py/bootburn_parser.py:43); with -u it skips the
  QSPI/NVMe erase and writes only the named partitions (bootburn_adb.py:1026-1057).
- flash_workspace/flash-images/FileToFlash.txt: A_MB1_BCT, A_secure-hv, A_sec-partition are all on
  /dev/block/810c5b0000.spi (QSPI).
- One run for all 3 avoids booting a half-updated slot A (Hafnium 2GB vs OP-TEE 32MB mismatch).
- Package verified before flashing: hafnium_t264_2gb.fip bytes inside flash-images/hafnium_t264_sigheader.fip.encrypt;
  tos_2gb.img inside sp_t264_aligned_blob_w_bin_sigheader.fip.encrypt after lz4 -d of the data from offset 12288
  (stock tos not); bootloader/ copy of the BCT misc dts has the TZDRAM override.
